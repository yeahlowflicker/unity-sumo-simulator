Welcome to the public repository of Unity-SUMO Simulator.

This is a utility which plays traffic scenarios generated by [Eclipse SUMO (Simulation of Urban MObility)](https://eclipse.dev/sumo/) in the [Unity game engine](https://unity.com).

This simulator enables custom logic to be added based on given SUMO traffic simulation data, hence allowing for custom behaviors of vehicles.

## Why was this work created?
The project was originally designed for a Realtime Traffic Monitoring and Analysis System (RTTMAS) of mine.

In RTTMAS, there will be smartphones/cameras attached to vehicles. They will periodically report their spatial information (GPS coordinates, heading, speed) and the license plates that they see at each moment.
Since SUMO only comes with GPS data, it is necessary to use Unity to further simulate the license plate recognition reporting events.

## Features
* 📍 GPS lat-lon coordinates to Cartesian coordinates conversion
* 🚗 Real-time vehicle traffic playback
* 📝 Vehicle detection and data reporting
* 📈 GPS precision error simulation
* 📁 SUMO-generated XML input & Simulation XML output

## How to Use

### Step 1: Configure the simulation
Specify the sim settings in the config menu.

![Screenshot 2025-01-13 at 6 48 22 PM](https://github.com/user-attachments/assets/d9c446b9-91e6-48a7-8940-a65803c1610e)

| Parameter | Description |
| --- | --- |
| `Input File Path` | The path to the SUMO-generated XML file |
| `Output File Path`  | The path at which this simulator will write its output to |
| `Active User Percentage` | How many percent of vehicles will make reports |
| `Event Report Interval (Seconds)` | How often will reports be made, in seconds |
| `Simulate GPS Error` | Whether or not to simulate GPS precision errors. If true, random noise values will be added to the lat-lon values of reports. |

### Step 2: Run the simulation
Press the `Run Simulation` button to start the simulation. It will take some time to initialize and process the simulation. Wait patiently until it ends.

![Screenshot 2025-01-13 at 6 51 31 PM](https://github.com/user-attachments/assets/fa94c6d3-9e0c-419a-92fc-070bbf7ccb65)

### Step 3: Locate the output XML
Once the simulation has completed, the config menu will show up once again. At this moment, the output data has already been written to the specified XML file.

![Screenshot 2025-01-13 at 6 53 49 PM](https://github.com/user-attachments/assets/3e2b82bf-5668-44e0-b8c2-77169f1460ea)

## Output XML
| Section | Description |
| --- | --- |
| `sim-configuration` | Contains metadata of the simulation config. |
| `pv-binding-facts` | Stores the real Vehicle-to-Plate-Number relations (a.k.a facts). |
| `simulation` | The main wrapper of all simulated data. Contains multiple `timestep` objects. |
| `vehicle-true-location` | Stores the real location, speed and heading data of vehicles. This is useful for debugging. |
| `user-location-reports` | Stores the spatial info reports made periodically by the report devices attached to vehicles. |
| `plate-recognition-reports` | Stores the plate recognition reports made by report devices. They contain estimated data of the recognized vehicles. |
